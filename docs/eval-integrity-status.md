## Held-out status update for #615 (2026-10-05)

The earlier row above was too broad: many evals do reserve a hash-based fifth, but that does not make a partition unseen when its cases or answers were already used during development. This inventory is based on the current result files and eval pages. It does not relabel any exposed pair as held out.

| --- | --- |
| QED Calcite | 375 converted cases, no held-out split; prover rules were developed with the pairs in view. Keep the score labelled tuned on test. |

| SQLSolver source suites | Calcite, Spark, TPC-H and TPC-C results have no held-out split and are labelled tuned on test. The separate mined Calcite corpus has a nominal new-pair partition, but its cases were exposed during rule development, so it is not an unseen score. |

`docs/evals/sqlsolver.md`, `docs/evals/conditional-equivalence.md`, `docs/evals/numeric-traps.md`, `docs/evals/rewrite-benchmarks.md` and the corresponding result files hold the per-eval details. `docs/evals/public-sources.md` is the source inventory. This audit found no ready, unused, labelled rewrite-pair source to add to QED/R-Bot/SQLSolver without first acquiring and pinning a new corpus and recording a baseline. A hash split of the existing exposed cases would not repair that gap.

The real BigQuery cost check also needs an authorized billing project and a BigQuery-accessible workload matching the recommendations. The harness already has local dry-run support, but no credential or workload can be inferred from this repository; project and billing identifiers must stay out of committed artifacts.
