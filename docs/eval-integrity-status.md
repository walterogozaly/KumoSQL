# Eval integrity audit status

An external auditor reviewed commit `b7d7dc6` (2026-09-29) and sent the [eval integrity audit](eval-integrity-audit-2026-10-02.md) on 2026-10-02. Master had moved about 400 pull requests since, so every finding was re-run on master (`a481075`, 2026-10-03) before anything was changed. This page records what each finding meant on master and what was done about it.

| Finding | On master before the fixes | Done |
| --- | --- | --- |
| Lifted CTE shadows a table, and the verifier approves it | Still a false proof. `SELECT a.x, b.x FROM (SELECT 1 AS x) a JOIN __lifted_subquery_001 b ON TRUE` was lifted into a CTE named `__lifted_subquery_001`, and `prove_equivalent` proved the two equal (with a table row `x = 7` they return `(1, 7)` and `(1, 1)`). The same capture existed in the prover's CTE canonicalization: a CTE renamed `__canonical_cte_001` matched a real table of that name, so a CTE self-join was proved equal to a join with the table. Canonicalization also matched references by exact case, while BigQuery resolves `FROM A` to CTE `a`, so two queries reading different CTEs were proved equal | The lifter skips every table and CTE name in the statement, case-insensitively, and the structural prover declines a query that reads a real table named like a CTE it generates. CTE references are matched case-insensitively, but only a reference to a CTE that is visible there is renamed: a non-recursive CTE is not visible in its own body or in an earlier one, so `FROM A` inside CTE `a` reads the physical table `A` and is left alone (an outside review showed `WITH a AS (SELECT s.x FROM A s) ...` and the same over `B` were proved equal). Every witness is a regression test (`tests/test_lift_subqueries.py`, `tests/test_equivalence.py`) |

MySQL and Calcite corpora have no boolean type, so `booleans_are_integers=True` reads `TRUE` as `1` there; only the SQLSolver bench (and through it the QED and Cosette evals) sets it.
